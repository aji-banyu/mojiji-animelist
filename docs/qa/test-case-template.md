# Test Case Template — Mojiji

> Template standar QA untuk pengujian fitur Mojiji berdasarkan PRD Revisi 4 dan Acceptance Criteria.

## 1. Test Case Information

| Field | Value |
|---|---|
| Test Case ID | TC-XXX-001 |
| Ticket ID | MJ-XXX |
| User Story ID | US-XXX |
| Feature | Nama fitur |
| Test Scenario | Skenario yang diuji |
| AC Reference | Positive / Negative — kriteria yang diuji |
| Test Type | Manual / API / Integration / E2E |
| Scenario Type | Positive / Negative |
| Priority | High / Medium / Low |
| Environment | Local / Staging / Production |
| Tester | Nama QA |
| Test Date | YYYY-MM-DD |
| Build / Version | Versi aplikasi yang diuji |
| Test URL / API Endpoint | URL halaman atau endpoint yang diuji |

## 2. Preconditions

Tuliskan kondisi yang harus dipenuhi sebelum pengujian dimulai.

## 3. Test Data

Tuliskan data dummy yang digunakan untuk pengujian.
Jangan mencantumkan password asli, token, API key, atau data sensitif.

## 4. Test Steps

1. Langkah pertama.
2. Langkah kedua.
3. Langkah ketiga.

## 5. Expected Result

Tuliskan hasil yang seharusnya terjadi sesuai Acceptance Criteria pada PRD.

## 6. Actual Result

Diisi dengan hasil yang benar-benar terjadi setelah pengujian dijalankan.

## 7. Test Status

Not Run / Pass / Fail / Blocked

## 8. Evidence

Tambahkan bukti pengujian yang relevan, seperti:

- Screenshot hasil pengujian.
- Response API dari Postman yang sudah disensor.
- Link GitHub Actions atau deployment log jika relevan.
- Bukti verifikasi migration atau backup jika relevan.

Jangan mencantumkan password, token, API key,
atau informasi sensitif.

## 9. Bug Reference / Notes

Tuliskan link GitHub Issue bug jika ditemukan, serta catatan tambahan.

## 10. Retest Information

| Field | Value |
|---|---|
| Retest Date | YYYY-MM-DD / N/A |
| Retest Result | Pass / Fail / Not Run |
| Notes | Catatan hasil pengujian ulang |
