# Bug Report Template — MOJIJI

> Template standar laporan bug QA berdasarkan Mini PRD MOJIJI Revisi 4 (Versi 1.4 — Docker/Migration Update).

## 1. Bug Information

| Field | Value |
|---|---|
| Bug ID | BUG-XXX / GitHub Issue |
| Related Ticket | MJ-XXX |
| User Story ID | US-XXX / N/A |
| Bug Title | Judul bug secara singkat dan jelas |
| Feature | Nama fitur |
| Severity | High / Medium / Low |
| Environment | Local / Staging / Production |
| Build / Version | Versi aplikasi atau commit SHA |
| Browser / Device | Browser dan perangkat yang digunakan |
| Reporter | Nama QA |
| Report Date | YYYY-MM-DD |

## 2. Bug Description

Jelaskan masalah yang ditemukan secara singkat dan jelas.

## 3. Preconditions

Tuliskan kondisi sebelum bug terjadi.

## 4. Steps to Reproduce

1. Langkah pertama.
2. Langkah kedua.
3. Langkah ketiga.

## 5. Expected Result

Tuliskan hasil yang seharusnya terjadi berdasarkan Acceptance Criteria.

## 6. Actual Result

Tuliskan hasil yang benar-benar terjadi ketika bug ditemukan.

## 7. Evidence

Tambahkan link screenshot, video, response API yang sudah disensor, atau log yang relevan.

## 8. Bug Status

Open / In Progress / Ready for Retest / Closed

## 9. Related References

| Field | Value |
|---|---|
| Test Case ID | TC-XXX-001 |
| GitHub Issue | Link issue |
| Fix Pull Request | Link PR / N/A |

## 10. Retest Information

| Field | Value |
|---|---|
| Retest Date | YYYY-MM-DD / N/A |
| Retest Environment | Staging / Production / Local |
| Retest Result | Pass / Fail / Not Run |
| Retest Evidence | Link evidence |
| Notes | Catatan pengujian ulang |

---

**Catatan keamanan:** Jangan mencantumkan password asli, token, cookie sesi, API key, kredensial database, atau data sensitif pada bug report dan evidence.
